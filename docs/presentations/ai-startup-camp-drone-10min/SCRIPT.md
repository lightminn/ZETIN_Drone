# 자작 드론 비행 제어 개발 결과 · 10분 발표 대본

## 1쪽 · 자작 드론 비행 제어 개발 결과

안녕하세요. 자작 드론의 프레임과 제어 보드, 펌웨어를 직접 연결하고 검증한
과정을 소개하겠습니다. 무엇을 만들었는지뿐 아니라, 문제가 생겼을 때 어떻게
재현하고 수정했는지를 결과 중심으로 말씀드리겠습니다.

오늘은 제작 범위와 SIL·벤치 검증, 테더 시험, 후속 개발 계획 순서로
말씀드리겠습니다.

전환: “먼저 상용 제품이 있는데도 직접 만든 이유부터 말씀드리겠습니다.”

## 2쪽 · 상용 제품과 자작 학습

상용 비행제어기는 빠른 설정과 현장 운용에 적합합니다. 검증된 생태계를 사용하는
것이 목적이라면 상용품이 더 좋은 선택일 수 있습니다.

저희는 센서 입력이 어떤 계산을 거쳐 모터 출력으로 바뀌는지 직접 보고, 오류를
주입해 안전 설계와 디버깅을 학습하기 위해 자작 시스템을 선택했습니다. 두 방식의
우열을 비교하는 것이 아니라 목적에 맞는 도구를 구분한 것입니다.

교육 현장에는 완성품만 쓰면 내부 인과가 가려지고, 전부 자작하면 준비·안전 부담이
커지는 간극이 있습니다. 학교·캠프·메이커스페이스 같은 운영기관을 우선 고객으로
가정하며, 교사·강사가 운영하고 학생이 사용합니다. 실제 기체·SIL·로그를 묶어 개념 → 오류
재현 → 측정 → 수정까지 경험하는 것이 제공 가치입니다. 초기 사업은 진행자 동반
파일럿으로 이 가치와 반복 운영 가능성을 확인하는 형태입니다.

전환: “그렇다면 실제 기체에서 직접 설계한 범위와 조달한 범위를 나눠 보겠습니다.”

## 3쪽 · 설계한 하드웨어와 조달 부품

왼쪽은 실제 벤치 조립 기체입니다. 모듈형 프레임과 비행제어 PCB, 전원·신호 배선
구조, 펌웨어와 지상 제어 프로그램, SIL 환경은 직접 설계했습니다.

모터와 ESC 각 네 개, 배터리와 프로펠러, ESP32-S3와 듀얼 IMU, BMM350은 상용
부품을 조달해 한 시스템으로 통합했습니다.

실제 전원은 12볼트 입력에서 ESC의 BEC를 거친 5볼트가 ESP32-S3로 들어가고,
ESP32-S3의 3.3볼트 출력이 센서로 이어집니다. 전원과 신호 경로를 구분해 두면
고장이 생겼을 때 원인을 순서대로 좁힐 수 있습니다.

여기서 사업 아이템은 완성 기체 한 대에 그치지 않습니다. 모듈형 기체·제어 보드,
실제 펌웨어, SIL, 로그 해석과 강사용 운영자료를 교육 모듈로 묶습니다. 같은
하드웨어로 센서·제어·안전 주제를 바꿀 수 있어야 기관이 반복 운영할 수 있습니다.

전환: “이 하드웨어는 한 번에 완성한 것이 아니라 시험 결과를 반영하며 바꿨습니다.”

## 4쪽 · 래피드 프로토타이핑

제작 과정은 설계 → 출력 → 시험·파손 → 측정 → 개선의 반복이었습니다. 출력물을
조립하면서 나사 간격, 적층 방향, 배선 공간을 확인하고, 손상된 위치와 간섭을
측정해 다음 CAD에 반영했습니다. 암과 상·하판을 나눈 구조라 손상된 부품만 다시
출력해 교체할 수 있습니다. 교육 중 파손이 생겨도 기체 전체를 교체하지 않고
해당 모듈만 복구할 수 있다는 점은 운영 중단 시간과 교체 부담을 줄이는 요소입니다.

제작 규모는 프린터 한 대와 첫 출력 성공을 기준으로 계산했습니다. 한 대는 프린터
점유 24~48시간, 직접 작업 6~10시간으로 약 2~3일, 열 대는
프린터 점유 240~480시간, 직접 작업 60~100시간으로 약 10~20일을 예상했습니다.

현재 부품비 합계는 한 대 22.2~23.3만 원, 열 대 222~233만 원입니다.
3901-L0X는 대당 4.8~4.9만 원의 선택 항목으로 기본 합계에서 제외했습니다.
이 수치로 파일럿에 필요한 장비 수, 출력 시간과 준비 인력을 계산하고, 운영 중
발생하는 재출력과 조립·교정·복구, 강사 준비 시간을 기록해 패키지 구성을
구체화할 계획입니다.

전환: “이제 네 모터가 기체의 자세를 어떻게 바꾸는지 보겠습니다.”

## 5쪽 · 네 모터로 만드는 비행

쿼드콥터는 네 로터의 합추력으로 뜨고, 모터별 출력을 다르게 배분해 자세를
바꿉니다. 좌우 출력 차이는 Roll, 앞뒤 차이는 Pitch, 서로 반대로 도는 모터 쌍의
차이는 Yaw 토크를 만듭니다.

현재 기체는 M1·M2가 시계 방향, M3·M4가 반시계 방향입니다. 모터 번호와 위치,
회전 방향, 코드의 믹서 부호가 하나의 계약이며, 하나라도 반대면 기울기를 줄이는
대신 키울 수 있습니다.

전환: “제어하려면 먼저 현재 자세를 추정해야 합니다.”

## 6쪽 · 자이로와 가속도계의 상보 관계

자이로는 빠른 회전을 잘 보지만 작은 바이어스를 계속 적분하면 오차가 누적됩니다.
가속도계는 중력 방향을 장기 기준으로 주지만 기체 가속과 모터 진동에 흔들립니다.

상보필터는 짧은 변화에는 자이로를 더 믿고, 장기적으로 가속도계의 중력 방향을
반영합니다. 가속도 크기가 1g에서 멀어질수록 가속도계 반영을 줄여 두 센서의
약점을 보완했습니다.

전환: “하지만 추정이 맞아도 모터 보정 방향이 반대면 자세는 안정되지 않습니다.”

## 7쪽 · 실제 디버깅과 SIL 검출력

실제 프로젝트에서는 두 IMU가 같은 움직임을 서로 다른 축과 부호로 표현한 문제를
원시값 비교로 찾았습니다. 센서축을 기체축에 맞춰 정렬한 뒤 자세 변화와 보정
방향을 다시 확인했습니다.

오른쪽은 별도의 host SIL 검출력 시험입니다. Roll 믹서의 보정량 R을 반대로
뒤집었을 때 정상 판정이 실패했고, 테스트가 해당 Roll 믹서 부호 오류를 잡는 것을
확인했습니다.

전환: “이 host SIL이 실제 비행 펌웨어를 어떻게 실행하는지 보겠습니다.”

## 8쪽 · 실제 펌웨어를 포함한 SIL

SIL 하니스는 제어식을 따로 복사하지 않고 실제 비행 펌웨어를 테스트에 포함합니다.
제어 태스크가 반복될 때마다 물리 모델이 직전 모터 출력으로 가상 기체를 움직이고,
그 상태의 듀얼 IMU 값을 다시 펌웨어에 넣어 폐루프를 만듭니다.

정상 조건에서는 Roll과 Pitch가 기준 근처로 수렴했고, Roll 믹서 부호를 뒤집은
변이는 실패했습니다.

전환: “이 폐루프 안에서는 두 제어기가 서로 다른 속도로 움직입니다.”

## 9쪽 · 캐스케이드 자세 제어

바깥 자세 루프는 목표 자세와 현재 자세의 차이를 목표 각속도로 바꿉니다. 안쪽
각속도 루프는 자이로와 목표를 비교해 더 빠르게 외란을 억제합니다.

마지막 믹서는 Roll, Pitch, Yaw 보정과 스로틀을 네 모터에 배분합니다. 화면은
안쪽 루프가 더 빠르다는 역할 관계를 보여주며, 구체적인 주기와 게인은 코드와
근거 문서에서 관리합니다.

전환: “Roll과 Pitch에는 중력이 기준이 되지만 Yaw에는 다른 기준이 필요합니다.”

## 10쪽 · Yaw 기준과 지자기 보정

중력은 Roll과 Pitch의 장기 기준이 되지만 수직축 회전인 Yaw는 알려주지 못합니다.
자이로만 적분하면 작은 바이어스가 시간에 따라 쌓입니다.

화면의 SIL에서는 초당 0.6도의 바이어스를 30초 주입했을 때 자이로 단독 오차가
18.3도, 지자기 융합은 2.4도였습니다. 빠른 회전은 자이로가, 장기 방위는 지자기가
맡는 구조입니다. 다음 단계에서는 모터 구동 중 지자기 값의 변화를 측정해
보정값을 확인합니다.

전환: “다음은 조종 신호가 끊겼을 때의 안전 전환입니다.”

## 11쪽 · 조종 신호 두절 시 안전 전환

신호가 끊기면 호버 스로틀 추정과 현재 스로틀을 확인합니다. 호버 추정이 없거나
저스로틀이면 즉시 모터를 끄고, 추정이 유효하며 기준을 넘을 때만 제한 하강으로
전환합니다.

착지를 판별하려고 모터 반응 프로브도 시험했지만 공중 0.061·0.097g과 접지
0.059~1.147g 범위가 겹쳤습니다. 지면에서도 반응이 남아 하나의 임계값으로
구분할 수 없었습니다.

따라서 프로브는 기록만 하고 landed=false를 유지해 착지 판정에서 제외했습니다.
다음에는 보드 워치독과 실제 착지 조건을 순서대로 검증할 계획입니다.

전환: “이제 실제 기체를 구동한 테더 시험을 보겠습니다.”

## 12쪽 · 테더 자세 제어 시험

왼쪽은 이동 범위를 줄로 제한한 실제 자세 제어 영상이고, 오른쪽은 별도 테더 로그
2,135행의 모터 평균입니다. M3는 1360.0마이크로초, M1은
1334.2마이크로초로 M3가 약 25.8마이크로초 높았습니다.

M3 근처에 연결된 테더 줄의 하중이 영향을 준 것으로 해석합니다. 영상과 로그는
서로 다른 테더 시험에서 얻었습니다. 다음 반복 시험에서는 테더 연결 위치를
바꾸고 모터별 추력 차이를 함께 비교할 계획입니다.

전환: “이 결과를 기준으로 다음 개발을 세 단계로 정리했습니다.”

## 13쪽 · 지상 로봇과 함께 쓰는 다음 단계

다음 개발은 단기·중기·장기로 나누고, 각 단계는 앞 단계의 검증 관문을 통과한 뒤
진행합니다.

단기에는 같은 절차로 자세 제어와 안전 전환을 반복하고, 3901-L0X 거리·광류를
제어에 연결하며 배터리 전압·전류·온도를 계측합니다. 같은 조건에서 센서와 안전
상태가 재현되는 것이 통과 기준입니다. 동시에 소수 기관과 진행자 동반 파일럿을
운영해 학생의 이해 변화, 강사 준비 시간, 모바일 동시 참여와 기체 복구 시간을
확인합니다.

중기에는 설계·출력·시험·파손·측정·재설계와 기체별 교정을 표준화합니다. BMS
상태 공유와 충전 도크는 무전원 정렬, 접촉 감지, 차단과 비상 절차부터 검증합니다.
또 프롭 OFF 벤치, 출입을 분리한 테더 공간, 승인된 자유비행 장소를 마련하고
sim-to-real 경로 계획을 단계적으로 시험합니다. 반복 제작 기록의 무게, 부품 수,
출력시간도 비교해 근거가 생긴 항목부터 경량화와 저가화를 판단합니다. 이 단계에서
강사용 운영자료와 실습 환경, 소수 기체를 표준화된 교육 패키지로 정리합니다.

장기에는 로봇개나 지상 로봇이 드론을 작업 지점까지 운반하고 유선 드론을 전개하는
협업으로 확장합니다. 정지 플랫폼과 무추력 테더, 격리된 테더 상승, 협업 임무
순서로 진행하며 명령 권한, 비상정지, 테더 장력과 엉킴을 확인합니다. 그 기반 위에
다기체 군집, 충돌 회피, 통신 이상 시 각 기체의 안전 전환을 검증하겠습니다.

전환: “이상으로 현재 결과와 다음 검증 계획을 말씀드렸습니다.”

## 14쪽 · 질의응답

프레임과 보드, 펌웨어와 검증 환경을 연결하고, 오류 재현부터 실제 테더 시험까지
진행했습니다. 다음 단계에서도 측정 결과를 설계와 제어 개선에 반영하겠습니다.

경청해 주셔서 감사합니다. 질문을 받겠습니다.
