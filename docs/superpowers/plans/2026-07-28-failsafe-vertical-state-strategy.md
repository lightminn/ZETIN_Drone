# 자동착륙 취약점 8건 해소 전략

2026-07-28. 코드리뷰 수정(커밋 358f2ef~54d6d9c) 이후 남은 구조적 취약점 8건의
해소 전략. 개별 패치 목록이 아니라 **의존 순서가 있는 3개 층**이다.

## 0. 8건은 독립적이지 않다

| # | 취약점 | 뿌리 | 해소되는 곳 |
|---|---|---|---|
| 1 | 임계값이 호버 추력에 비연동 | 수직 상태 없음 | Layer 1 |
| 2 | `saw_impact`에 시간 제약 없음 | 수직 상태 없음 | Layer 1 (문제 소멸) |
| 3 | 지면효과 오검출 | 수직 상태 없음 | Layer 1 (문제 소멸) |
| 4 | `safety_lock` 양 코어 경합 | 독립 | Layer 2 |
| 5 | 타임아웃이 사실상 주 경로 | 수직 상태 없음 | Layer 1 |
| 6 | `Failsafe_Phase` 소비자 없음 | 관측 불가 | Layer 0 |
| 7 | 가속도 보정 없음 | — (Layer 1의 전제) | Layer 1 |
| 8 | 복구 경로 없음 | 독립 | Layer 2 |

1·2·3·5는 한 뿌리다 — **failsafe가 기체의 수직 상태를 모른다.** 고도도
수직속도도 호버추력 추정도 없으니 변하는 양을 고정 상수로 대신하고 있다.

### 왜 적분이 답인가

원래 설계가 실패한 지점이 여기다. 등속 하강과 정지는 **순간** 가속도로
구분되지 않는다(둘 다 1g). 그러나 적분하면 구분된다:

- 등속 하강: `|a| = 1g`, `v_z = 상수 ≠ 0`
- 접지 후 정지: `|a| = 1g`, `v_z = 0`

스파이크 검출은 이 정보를 못 쓰기 때문에 택한 우회로였다. 지면효과도
마찬가지로 갈린다 — 지면효과는 하강을 **감속**시키지만 **정지시키지는
못한다.** v_z는 그 차이를 본다.

### 실현 가능성 검산

`v_z`를 적분으로 얻을 때 지배적 오차원을 따져야 한다.

**자세 오차는 문제가 아니다.** 자세 추정이 θ만큼 틀려도 수직 성분은
`1g·cos(θ)`이므로 오차가 θ의 2차다. θ=2°면 0.0006g = 0.006 m/s², 5초
적분해도 0.03 m/s. (`g·sinθ`는 수평 누설이지 수직이 아니다.)

**지배적 오차는 가속도 스케일 하나다.** 현재 실측 바이어스 +0.8%
(정지 시 `|a|` 중앙값 1.007~1.009g) = 0.078 m/s² → 5초에 **0.39 m/s**.
목표 하강률 0.4 m/s와 같은 크기라 보정 없이는 쓸 수 없다.

정지 시 `|a|`로 스칼라 스케일 보정(`k = 1/|a|_rest`)을 하면 잔차는 0.1%
수준 → 5초에 0.05 m/s. 하강률 대비 12%로 충분하다. **그래서 7번이 선택이
아니라 전제조건이다.**

진입 시 `v_z = 0`으로 리셋하므로 적분 구간은 하강 5초로 제한된다. 비행
전체를 적분하지 않는다.

⚠️ `FS_MAX_MS`를 10초로 올리면 드리프트도 2배(0.1 m/s)가 된다. 판정
임계를 그에 맞춰 재검토해야 한다.

### 스칼라 스케일 보정의 한계 (의도적 선택)

축별 오프셋 보정은 6면 캘리브레이션이 필요하고, 정지 1회 측정으로는
자세를 모르므로 3축 분리가 불가능하다. 반면 **착지 판정과 v_z 모두 `|a|`
기반**이므로 스칼라 스케일만으로 관측된 오차의 대부분을 제거한다. 축별
오프셋은 별도 과제로 남긴다(현재 근거 없음).

## Layer 0 — 관측 가능하게 만들기

**이게 없으면 나머지는 추측이다.** Layer 1의 모든 항목이 여기에 의존한다.

### 0-A. SIL 플랜트에 수직 동역학 추가
`PlantState`에 `z`, `v_z`. 스로틀→추력 모델, 지면 접촉(반력·정지), 지면효과
(고도에 따른 추력 증배)를 넣는다.

지금은 자동착륙을 검증할 수 있는 곳이 실기밖에 없다. 이걸 만들면 하강,
착지, **공중 오검출**, 타임아웃을 전부 자동 검증할 수 있고, 위험해서 실기로는
재현하면 안 되는 시나리오를 안전하게 돌릴 수 있다.

검증 대상 시나리오(최소):
- 정상 하강 → 접지 → `FS_CUT_LANDED`
- 진입 스로틀이 호버보다 높음 → 상승 → 현재 코드로는 타임아웃 (1번 재현)
- 지면효과 구간 통과 중 오검출하지 않음 (3번 재현)
- 돌풍 스파이크 후 잔잔한 구간 → 오검출하지 않음 (2번 재현)

**먼저 현재 코드로 위 넷을 돌려 1·2·3번이 실제로 재현되는지 확인한다.**
재현되지 않으면 내 분석이 틀린 것이므로 Layer 1 설계를 재검토한다.

### 0-B. 하강 구간 고속 캡처
텔레메트리는 50ms(20Hz)인데 접지 스파이크는 10~100ms다. **현행 로그로는
스파이크를 볼 수 없다** — 지금 `docs/power_on_bench_procedure.md` Stage E-4가
지시하는 측정은 실행 불가능하다.

하강 중 원시 `|accel|`(및 `v_z` 추정치)을 1kHz 링버퍼에 담고 컷 이후 UDP로
덤프한다. 5초 × 1kHz × float 2개 = 40KB — RAM 여유(현재 17% 사용) 안이다.
전송은 컷 이후이므로 비행 중 부하가 없다.

이게 `FS_LAND_*` 상수 확정의 유일한 근거다.

### 0-C. `Failsafe_Phase` 표시
`monitor_telemetry.py`와 `analyze_flight_log.py`가 이 필드를 **0번 참조**한다.
그런데 Stage E는 조종자에게 비행 중 실시간으로 보라고 한다. 두 도구에
`Failsafe_Phase`·`Trim_Roll`·`Trim_Pitch`를 추가한다. → **6번**

가장 싸고 벤치를 당장 막고 있는 항목이다.

### 취약점 5는 이미 해소됐다

"모든 자동착륙이 타임아웃으로 끝난다"는 주장은 **구 코드(±0.05g)에 대해서만
맞았다.** 실측 로그로 400ms 확정창이 통째로 허용오차 안에 들어오는 비율:

| 로그 | ±0.05g (구) | ±0.10g (현) |
|---|---|---|
| 040715 | 66.5% | 95.6% |
| 040904 | 68.5% | 92.7% |
| 041032 | 84.9% | 97.1% |

커밋 4174172의 허용오차 확대만으로 안정 조건은 실현 가능해졌다. V1의 성공은
SIL 인공물이 아니라 실측이 뒷받침한다.

⚠️ 부수 정정: LPF가 노이즈를 크게 줄일 것이라는 최초 계산은 **백색잡음
가정이라 틀렸다.** 실측에서 5Hz LPF는 sd를 0.0503 → 0.0470으로 거의 줄이지
못한다. 노이즈의 지배 성분이 5Hz 아래의 실제 기체 운동이기 때문이다.

### 그런데 이게 반대편을 악화시킨다

안정 조건이 쉬워진 만큼(93~97%) 공중 오검출을 막는 것은 `saw_impact` 하나뿐이다.
그리고 V2가 그 문지기가 헐겁다는 것을 보여줬다.

**신규 취약점 9 — `saw_impact`는 접지에 특이적이지 않다.** V2에서 기체가
상승하는 동안 0.501s에 `saw_impact`가 섰다. 상승 가속도가 1g+0.25g를 넘었기
때문이다. 지면 반력이든 상승 가속이든 돌풍이든 **위쪽 가속이면 무엇이든**
접지 증거로 채택된다.

정리하면 같은 결론이다:
- 구 코드: 너무 엄격 → 안 걸림 (취약점 5)
- 현 코드: 안정 조건은 쉬워졌으나 문지기가 비특이적 → **공중에서 걸림** (취약점 2·9)

**가속도 크기만으로는 이 일을 할 수 없다.** Layer 1(v_z)이 유효하다.

### 0-A′ 후속 측정 (진동 모델 + V3 재설계)

SIL에 실측 기반 저주파 진동 모델(기본 OFF, 결정적)을 넣고 다시 측정했다.

**취약점 3 — 반증.** V3를 실제로 하강하게 고쳐 `k_ge`를 0.15/0.25/0.35로 훑었다.

|---|---|---|---|

못한다. 취약점 3은 목록에서 닫는다.

**취약점 5 — 반증(이미 해소).** 노이즈 sd를 0.02/0.04/0.06g로 훑어도 V1은
계속 `FS_CUT_LANDED`로 착지했다. 다만 **검출이 0.71초 지연**된다(2.925s →

**취약점 2·9 — 확정.** V4는 노이즈 ON/OFF 무관하게 **정확히 같은 1.901초**에
공중 컷했다(접지 2.309초, 약 1m 상공). 노이즈가 원인이 아니라 **로직이
원인**이라는 뜻이다.

### v_z 적분의 타당성 (실측으로 확인)

저주파 노이즈를 적분하면 랜덤워크가 커져 v_z가 못 쓸 것이라는 우려가 있었다.
모터 OFF 정지 구간에서 **센서 노이즈 바닥**을 재보니:

    센서 노이즈 바닥 = 0.0006 g   (무장 중 관측 0.03~0.05g보다 두 자릿수 작음)

즉 무장 중의 0.04g는 거의 전부 **실제 기체 운동**이지 센서 오차가 아니다.
실제 운동은 v_z가 추적해야 할 신호지 오차가 아니다. 센서 노이즈만의 적분
드리프트는 τ=0.2s, T=10s에서도 **0.012 m/s**로 무시할 수 있다.

따라서 v_z의 지배 오차는 여전히 **스케일 오차 하나**(0.8% → 5초에 0.39 m/s)이며
1-A로 잡는다. **Layer 1은 실현 가능하다.**

### 남은 숙제

- **V3 재설계**: 진입 스로틀이 호버보다 높아 기체가 상승해버렸다. 지면효과
  구간을 실제로 통과하도록 다시 짜야 3번을 판정할 수 있다.
- **SIL에 진동 모델이 없다**: 현재 accel 주입은 2 LSB dither뿐이라 실측 sd

  노이즈를 넣어야 한다. 특히 **오검출 시나리오는 노이즈 없이는 낙관적으로
  나온다.**
- `k_ge=0.15`(추력 +15%)는 임계 0.25g보다 작아 지면효과만으로는 `saw_impact`를
  못 세운다. 실제 지면효과는 최대 +30%까지 가므로 파라미터 의존적이다.
- `LandDetector`가 `pid_task` 지역변수라 계측 seam이 없어 SIL이 shadow 복제본을
  돌려야 했다. 검증 신뢰도를 위해 관측 가능하게 만드는 편이 낫다.

## Layer 1 — 상수를 추정으로 대체

### 1-A. 가속도 스케일 보정 → **7번**
`calibrate_bias()`는 이미 정지 대기를 하고 자이로만 보정한다. 같은 정지
구간에서 `|a|`를 평균해 `accel_scale = 1.0 / |a|_rest`를 구해 적용한다.
움직임 판정(`BIAS_MOVEMENT_THRESH`)은 그대로 재사용한다.

검증: 보정 후 정지 `|a|` 중앙값이 1.000±0.002g인지.

### 1-B. 호버 스로틀 추정기 → **1번**
무장 상태에서 수평이고 `|a| ≈ 1g`가 유지되는 동안의 스로틀이 곧 호버 추력이다.
이를 LPF로 계속 추적한다(`hover_throttle_est`).

그 위에서 두 상수를 **상대값으로** 바꾼다:
- 하강 목표 = `hover_throttle_est − FS_DESCENT_DELTA_US`
  (진입 스로틀이 아니라 **호버 추정치** 기준. 조종자가 상승 중이었어도
  실제로 하강한다.)
- 지상컷 판정 = `base_throttle < hover_throttle_est − FS_GROUND_MARGIN_US`

추정치가 없을 때(무장 직후, 아직 호버한 적 없음)의 폴백이 필요하다:
추정 유효 플래그가 서기 전이면 **지상으로 간주해 즉시 컷**한다. 호버한 적이
없으면 공중에 있을 수 없다는 논리로, 안전한 쪽 폴백이다.

### 1-C. 수직속도 기반 착지 판정 → **2·3·5번**
진입 시 `v_z = 0` 리셋 후 `v_z += (a_world_z − g)·dt`로 적분한다.

판정: **하강을 명령했는데 `v_z`가 0 근처로 돌아와 유지되면 접지.**
`min_descend` 게이트는 유지하되(판정만 지연, 증거는 항상 수집 — 이번 리뷰의
교훈), 스파이크 검출은 **보조 신호**로 격하한다.

이러면:
- 2번: 스파이크의 시간 제약 문제가 사라진다(주 신호가 아니게 됨)
- 3번: 지면효과는 감속시킬 뿐 `v_z`를 0으로 만들지 못한다
- 5번: 타임아웃이 예외 경로로 돌아간다

## Layer 2 — 구조 정리 (Layer 0·1과 독립)

### 2-A. `safety_lock` 단일 writer → **4번**
`fs_phase`와 같은 모양의 경합이 그대로 남아 있다. `pid_task`가 765·836·859·
894행에서 `true`를, `udp_task`가 1252행에서 `false`를 쓴다. `fs_phase`에
적용한 것과 같은 방식(요청 플래그를 Core 0이 세우고 실제 전이는 Core 1이
수행)으로 정리한다.

### 2-B. 복구 경로 → **8번**
링크가 살아나도 자동 복귀는 위험하다(하강 중 재진입 반복). 명시적 `resume`
명령으로만 `FS_DESCENDING → FS_NONE` 복귀를 허용한다. 조건: RC가 실제로
살아있고(최근 수신), 자세가 정상이며, IMU가 살아있을 것.

## 실행 순서

```
0-C (표시)        ─┐  벤치를 당장 막고 있음. 먼저.
0-A (SIL 수직)    ─┼─→ 1-A (스케일 보정) ─→ 1-C (v_z 판정)
0-B (고속 캡처)   ─┘                    └─→ 1-B (호버 추정)
2-A, 2-B          독립. 아무 때나.
```

엄격한 의존은 하나뿐이다: **0-A 없이 1-C를 만들면 검증할 곳이 없다.**
1-A는 1-C의 수치적 전제조건이다.

## 검증 원칙

- 각 항목마다 회귀 테스트를 먼저 RED로 확인한 뒤 GREEN으로 만든다.
- 핵심 가드는 변조로 판별력을 증명한다(이번 리뷰에서 이게 유일하게
  효과적이었다).
- **0-A 완료 후, 현재 코드로 1·2·3번이 SIL에서 실제로 재현되는지 먼저
  확인한다.** 재현되지 않으면 분석이 틀린 것이다.

## 이 전략이 해결하지 못하는 것

- **위치 유지는 여전히 불가능하다.** 위치 센서가 없어 바람에 흘러간다.
  "제자리 착륙"은 이 전략 이후에도 성립하지 않는다.
- 축별 가속도 오프셋(6면 캘리브레이션 필요)은 범위 밖이다.
- 기압센서를 달면 `v_z` 추정을 고도원으로 교체할 수 있다. 1-C의 인터페이스를
  교체 가능하게 설계하되, 이번 범위에는 넣지 않는다.
