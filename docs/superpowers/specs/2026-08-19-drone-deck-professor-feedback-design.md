# 드론 발표자료 교수 피드백 반영 설계

## 목표

본편 84장과 10분 결과발표 14장의 기술 중심 흐름을 유지하면서, 자작 비행제어기의
목적을 상용품과의 우열 비교가 아닌 학습·검증 목적으로 바로잡는다. 실제 제작 사진과
간결한 Python 정지 도판을 중심으로 실패 재현·디버깅, 래피드 프로토타이핑,
제작 규모·비용, 단기·중기·장기 목표를 한눈에 보이게 한다.

## 고정 계약

- 본편은 84장, 결과발표는 14장으로 유지한다.
- 기술이 본론이고 사업·교육 가능성은 도입과 결론의 보조 맥락이다.
- 실제 사진은 정지 사진으로 유지한다. 여러 조건을 비교하는 개념 도판도 모든 상태를
  한 화면에 놓은 Python/Manim PNG로 사용한다.
- 실제 제작·벤치·SIL·테더·계획의 증거 수준을 섞지 않는다.
- 팀 이름, 구체적인 날짜, 커밋 해시, 발표 시간은 화면에 넣지 않는다.
- 사용자가 다시 요청하기 전 PPTX와 PDF는 재생성하지 않는다.

## 메시지 원칙

### 상용품과 자작 시스템

- 상용 비행제어기는 빠른 운용, 검증된 생태계, 현장 적용에 유리하다.
- 자작 시스템은 센서 입력부터 모터 출력까지 관찰하고, 오류를 의도적으로 재현하며,
  안전 설계와 테스트를 직접 실습하기 위해 선택한 학습 플랫폼이다.
- `듀얼 IMU 구성` 자체를 상용품을 쓰지 않은 이유로 제시하지 않는다.
- 화면의 결론은 `우열이 아니라 목적의 차이`로 고정한다.

### 실패와 디버깅

- 결과만 보여주지 않고 `증상 → 기록·비교 → 원인 추적 → 오류 재현 → 수정 검증`을
  실제 프로젝트의 학습 순환으로 제시한다.
- SIL의 부호 반전 주입은 자이로 부호가 아니라 Roll 믹서 보정 방향을 뒤집은 시험임을
  유지한다.
- host/SIL 결과를 보드 재부팅이나 자유비행 검증으로 확대하지 않는다.

### 래피드 프로토타이핑

- 실제 출력물 사진을 가장 크게 사용하고 `CAD → 출력 → 조립 → 수정` 네 동작만
  보조 도식으로 둔다.
- 나사 간격, 적층 방향, 배선 통로는 사진에서 확인한 대표 수정 사유로 짧게 표시한다.
- `Maker Space 박근원 선생님의 장비·제작 지원에 감사드립니다.`를 화면 하단에 넣는다.
- 확인되지 않은 특정 출력 소요시간이나 성공 횟수는 주장하지 않는다.

### 제작 시간과 비용

- 저장소에 완전한 BOM, 슬라이서 출력, 실제 작업시간 기록이 없으므로 모든 값은
  `현재 형상·부품 보유 기준의 예비 산정`으로 표시한다.
- 시간은 `3D 프린터 장비 점유`, `사람이 직접 하는 조립·납땜·점검`, `전체 경과`를
  분리한다. 10대는 프린터 한 대에서 순차 출력하는 기준과 병렬 장비의 효과를 구분한다.
- 비용은 최소한 모터 4개, ESC 4개, 비행제어 보드·센서, 3D 프린팅 재료를 분리하고,
  완성 기체 총액에는 배터리·프로펠러·커넥터·체결부품을 별도 묶음으로 더한다.
- 인건비, 개발비, 장비 감가, 배송·관세는 화면 합계에서 제외하고 발표자 노트와
  근거 문서에 명시한다.
- 변동 가격은 단일 숫자 대신 출처를 가진 범위로 표시한다. 10대 비용은 단가 범위의
  단순 곱이며 양산 할인 가정을 넣지 않는다.

## 본편 배치

### 14장 — 상용 제품과 자작 학습

- 제목: `상용 제품과 자작 학습`
- 왼쪽: `운용`과 `학습·검증`의 목적 비교
- 오른쪽: 실제 자작 비행제어 보드 사진
- 하단: `상용품이 필요한 현장과 자작이 필요한 학습의 목적이 다르다.`

### 22장 — 1대와 10대 제작 규모

- 제목: `1대와 10대 제작 규모`
- Python 정지 도판으로 1대와 10대의 장비 점유·직접 작업을 같은 기준선에서 비교한다.
- 비용은 모터·ESC·보드/센서·프레임·기타의 누적 막대로 표현한다.
- 가정과 제외 범위는 화면 하단 한 줄과 발표자 노트에 둔다.

### 25장 — 래피드 프로토타이핑

- 제목: `3D 프린팅 래피드 프로토타이핑`
- 실제 출력물 사진과 `CAD → 출력 → 조립 → 수정` 순환을 한 화면에 배치한다.
- 긴 실패 사례 문장 대신 `나사 간격`, `적층 방향`, `배선 통로` 세 표지만 사용한다.
- Maker Space 박근원 선생님 감사 문구를 포함한다.

### 43장 — 문제 추적과 수정

- 제목: `문제 추적과 수정`
- 부호·축 오류를 예로 들어 증상에서 수정 검증까지의 경로를 보여준다.
- 결론: `실패를 재현하고 원인을 좁혀 검증까지 연결하는 디버깅 학습`.

### 83장 — 단기·중기·장기 목표

- 단기: 단일 기체의 반복 가능한 자세 제어, 거리·광류 연결, 착지 판단 검증
- 중기: 반복 제작·교정 절차, sim-to-real 경로 계획, 다기체 운용 기반
- 장기: 군집 제어, 충돌 회피, 통신 이상 시 집단 안전
- 각 단계는 이전 단계의 통과 기준을 충족한 뒤 진행하는 계획으로 표시한다.

## 10분 결과발표 배치

- 2장: `상용 제품과 자작 학습`으로 재작성한다.
- 4장: 실제 CAD·출력물·PCB 사진을 유지하며 래피드 프로토타이핑과 1대/10대
  예비 산정을 압축해 넣는다.
- 7장: 부호 계약 설명을 `문제 발견 → 원인 추적 → 재현 → 수정` 결과 중심으로 바꾼다.
- 9장: 고정된 보편 숫자 대신 안쪽 루프와 바깥 루프의 상대 시간척도를 설명한다.
- 11장: 특정 시간 상수보다 조건별 안전 전환과 검증 경계를 보여준다.
- 13장: `단기·중기·장기 목표`로 바꾼다.
- 14장: 제작 결과, 검증 역량, 교육 적용 가능성을 기술 중심으로 요약한다.

## 시각 언어

- 흰 배경, UOS 파랑, 짙은 먹색을 유지한다.
- 녹색은 정상·확인, 노란색은 계획·주의, 빨간색은 실제 오류·위험에만 사용한다.
- 최소 본문 글자 크기는 기존 22px 계열을 유지하고, 표보다 사진·막대·순환선을 먼저 쓴다.
- `핵심은`, 수사적 질문, 숫자 카드, 광고 문구를 사용하지 않는다.
- 완전한 문장은 `~이다`로, 짧은 라벨은 명사형으로 끝낸다.

## 검증 계약

- 본편 84장, 결과발표 14장 계약과 모든 발표자 노트를 유지한다.
- 14·22·25·43·83장과 결과발표 2·4·7·13장은 Chrome 1280×720 캡처에서
  겹침·잘림·한 단어 내부 줄바꿈이 없어야 한다.
- `듀얼 IMU 구성`이 상용품 비사용 이유로 남아 있지 않아야 한다.
- `상용품이 필요한 상황`, `학습 목적`, `디버깅`, `박근원`, `단기`, `중기`, `장기`가
  각각 지정 장표에 존재해야 한다.
- 시간·비용 수치에는 가정, 범위, 제외 항목이 연결되어야 한다.
- 기존 실사 영상 개수와 자동재생·이탈 시 정지/초기화 계약을 보존한다.
- PPTX/PDF는 이 변경의 검증 대상에서 제외한다.
