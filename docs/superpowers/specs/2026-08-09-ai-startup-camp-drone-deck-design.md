# AI 창업캠프 드론 발표자료 저장소 편입 설계

## 목적

`AI 창업캠프 드론 발표-handoff.zip`의 메인 77장 HTML 발표자료를 현재
`zetin-drone` 구현과 실측 기록에 맞게 고치고, 이후 Codex로 계속 편집할 수 있는
자체 완결형 HTML 원본으로 저장소에 편입한다.

HTML을 단일 원본(source of truth)으로 유지한다. PPTX나 PDF는 내용이 확정된 뒤
생성하는 배포 산출물이며 이번 범위에는 포함하지 않는다.

## 대상과 기준 시점

- 입력 원본: ZIP의 `ai/project/ZETIN Drone 기술 교안.dc.html`
- 대상 슬라이드: 메인 발표자료 77장
- 내용 기준일: 2026-08-09
- 코드 기준: 현재 브랜치 `feat/magcal-ellipsoid-fit`의 `88d3735`
- 현재 브랜치가 포함하는 최신 자기계·센서·자동착륙 변경을 발표 내용에 반영한다.

기술 수치와 상태가 충돌하면 다음 우선순위를 적용한다.

1. 현행 펌웨어와 PC 도구
2. 날짜가 명시된 최신 실측·정정 문서
3. UDP 스키마와 로그 형식 문서
4. 발표자료에 동봉된 2026-07-24~27 로그와 차트 데이터
5. `docs/project_overview.md` 등 개요 문서

개요 문서에 남은 오래된 설명을 발표자료의 근거로 사용하지 않는다.

## 저장 구조

발표자료는 다음 경로에 둔다.

```text
docs/presentations/
├── README.md
└── ai-startup-camp-drone/
    ├── README.md
    ├── SOURCES.md
    ├── index.html
    ├── deck-stage.js
    ├── support.js
    ├── chartdata.json
    ├── assets/
    │   ├── hover_demo.mp4
    │   ├── chart_*.png
    │   ├── image*.(png|jpeg)
    │   └── pcb_*.png
    └── vendor/uos-slide-template/
        ├── README.md
        ├── _ds_bundle.css
        ├── _ds_bundle.js
        ├── _ds_manifest.json
        ├── styles.css
        └── fonts/
```

다음 파일은 편입하지 않는다.

- ZIP 안의 `uploads/` 중복 발표자료
- 원본 생성 도구의 `.thumbnail`, `scratchpad.md`
- 2026-07-24~27 CSV 복제본
- 최종 확정 전 PDF 또는 PPTX

CSV를 제외해도 발표 화면은 사전 생성된 차트 이미지와 `chartdata.json`으로
동일하게 재생된다. 시연 영상과 로컬 폰트는 오프라인 발표를 위해 포함한다.

## 슬라이드 수정 범위

77장 구성과 UOS 시각 체계는 유지한다. 슬라이드를 새로 늘리기보다 기존 설명,
수치, 표, 발표자 노트를 같은 자리에서 교체한다.

### 센서·필터·좌표계

- 27·72번: 텔레메트리를 34개에서 현행 65개 필드로 바꾼다. CSV는 수신 시각을
  포함해 66열임을 구분한다. 20Hz 상태 텔레메트리와 1kHz 원시 IMU 스트림을
  별도 경로로 설명한다.
- 31번: `현재 α=0.98`을 제거하고 `0.999 / 0.9995 / 0.9998` 적응형 α를
  가속도 신뢰도에 따라 선택한다고 설명한다.
- 32번: 실제 자기계 보정은 250Hz에서 `K_MAG=0.001`, 시정수 약 4초임을 표시한다.
  1kHz에서의 `α=0.99975`는 현행 구현값으로 제시하지 않는다.
- 37번: 자이로 기체축 변환을 Roll `+sensor Y`, Pitch `-sensor X`,
  Yaw `-sensor Z`로 고친다. 가속도 변환은 기존 `+Y/-X/+Z`를 유지한다.

### 자기계

- 49~52번: 2026-07-27의 `18.3° → 2.4°`, `+3.64 → +0.02°/100µs`는
  날짜가 붙은 역사적 실측으로 유지한다.
- 최신 상태로 min/max 보정이 제약 타원체 hard/soft-iron 보정으로 교체됐고,
  2026-08-04 보드 재검증과 간섭 램프 검증을 통과했음을 추가한다.
- 53번: 펌웨어 내부 부팅값은 OFF지만 정상 지상국 운용 기본값은 ON이며
  `--no-mag` 또는 `mag off`로 끈다는 구조로 바꾼다.

### 자동착륙과 거리·광류 센서

- 57번: RC 타임아웃은 자동 하강, IMU 전멸·과도 기울기·수동 정지는 즉시 컷이라는
  분리는 유지한다. 착지 감지가 모터를 끈다는 설명은 삭제한다.
- 58~61번은 `시도 → 실비행 반증 → 현재 조치` 순서로 재구성한다.
  - 공중이라고 분류한 데이터가 실제로는 지면 데이터였다는 정정을 표시한다.
  - 공중 프로브 분포는 아직 측정되지 않았다고 명시한다.
  - `0.038~0.051g 대 0.063~0.139g`, `0.011g`, `1.794→0.959초`를
    현재 유효한 안전 근거로 사용하지 않는다.
  - 프로브는 텔레메트리 기록용이고 착지 결정에서는 제외됐음을 표시한다.
  - 현재 자동착륙은 `FS_MAX_MS=3000`의 시간 기반 하강이다.
  - 실내 저고도 자동착륙은 아직 신뢰하지 않는다는 운용 제약을 표시한다.
- `고도 센서 미탑재`를 삭제한다. Matek 3901-L0X 거리·광류 데이터는
  GPIO16으로 수집되어 텔레메트리 60~64번에 들어가지만 아직 제어 결정에는
  사용하지 않는다고 설명한다.

### 실측 성과와 상태

- 68번의 2026-07-27 테더 구간 `106.4초`, Roll 표준편차 `1.65°`,
  Pitch 표준편차 `1.23°`는 유지한다. 안정 비행 전체가 검증됐다는 의미로
  확대하지 않는다.
- 69번은 같은 106.4초 전체 구간을 재현 가능한 기준으로 사용한다.
  M1 평균 약 `1334.2µs`, M3 평균 약 `1360.0µs`, 차이 약 `25.8µs`로 바꾸고
  슬라이드 표시값은 반올림해 `약 26µs`로 쓴다.
- 모터 차동의 원인은 무게중심으로 확정하지 않는다. 무게중심, 모터·프롭·ESC,
  테더, 프레임 또는 공력 비대칭과 일치하는 지속 제어 바이어스로 설명한다.
- 75번에 2026-08-01 첫 실비행 `176.2초`, 고장 플래그 0건,
  PID 루프 평균 1000Hz·최소 999Hz, 자기계 ON, Yaw hold 잠금 91.9%를 추가한다.
- 해당 기록이 테더 없는 비행이라고 문서에 명시돼 있지 않으므로 자유 호버 완료로
  표현하지 않는다.
- 안정 호버와 자동착륙을 완료 상태로 올리지 않는다. 현행 저장소의
  `실험 중인 비행 후보` 경계를 유지한다.
- 76번의 `센서를 추가한다`는 계획을 `이미 연결된 거리·광류 센서를 제어에
  사용하고 검증한다`로 바꾼다.

## 시각·문체 원칙

- 기존 UOS 파란색, Noto Sans CJK KR, 16:9 레이아웃을 유지한다.
- 한 장에 새로운 카드나 문단을 과도하게 추가하지 않는다.
- 내부 구현 명칭만 나열하지 않고 비전공자가 이해할 수 있는 결과 중심 문장으로 쓴다.
- `검증 완료`, `실험 중`, `미측정`, `제어 미사용`을 서로 다른 상태로 명확히 쓴다.
- 역사적 결과에는 날짜와 시험 조건을 붙인다.
- 발표자 노트도 화면 본문과 같은 현재 결론을 사용한다.

## 검증

### 구조 검사

- `index.html`의 `<section>` 수가 정확히 77개다.
- HTML·CSS·JS가 참조하는 로컬 파일이 전부 존재한다.
- `uploads/`, CSV, PDF, PPTX가 발표자료 폴더에 들어가지 않는다.
- 최대 파일은 100MB 미만이며 영상은 일반 Git 객체로 관리한다.

### 내용 검사

다음 오래된 표현이 발표자료에서 사라졌는지 기계적으로 확인한다.

- `현재 사용값 — α = 0.98`
- `기체 roll 각속도 = − 센서 Y`
- `기체 pitch 각속도 = + 센서 X`
- `34개 항목`
- `고도를 재는 센서는 아직 달지 않았습니다`
- `센서 미탑재`
- `기본값 OFF`
- `벤치에서 프로빙 반응을 반복 측정하며 임계값을 다듬고 있습니다`

또한 현행 값과 상태 문구가 존재하는지 확인한다.

- `0.999`, `0.9995`, `0.9998`
- `65개 필드`, `66개 열`, `1kHz`
- `FS_MAX_MS=3000` 또는 같은 의미의 `3초`
- `176.2초`
- `3901-L0X`
- `제어에는 아직 사용하지 않음`

### 렌더링 검사

- 로컬 HTTP 서버에서 첫 장, 수정이 집중된 31·37·53·58~61·68·69·75·76번을
  렌더링한다.
- 화면 잘림, 겹침, 과도하게 작은 글씨, 누락 이미지가 없는지 확인한다.
- `hover_demo.mp4`가 존재하고 `ffprobe`가 비디오 스트림을 읽는지 확인한다.
- 렌더링 검사는 HTML 정적 검증이며 실제 현장 프로젝터·오디오 재생 검증을
  대신하지 않는다.

## Git 범위

- 기존 작업 트리의 `docs/README.md`, `docs/cascade_vs_single_pid.typ`,
  `docs/cascade_vs_single_pid.pdf`는 수정·스테이징·커밋하지 않는다.
- 설계 문서는 별도 커밋한다.
- 구현 커밋은 `docs/presentations/` 아래의 새 파일만 포함한다.
- 구현 완료 후 현재 `feat/magcal-ellipsoid-fit` 브랜치를 `origin`에 푸시한다.
  이 푸시는 해당 브랜치에 이미 존재하는 자기계 보정 커밋도 함께 공개한다.
- main 머지나 PR 생성은 이번 범위가 아니다.

## 완료 조건

1. 77장 발표자료에 위 기술·상태 수정이 전부 반영돼 있다.
2. 저장소만 복제해도 로컬에서 발표자료와 영상을 열 수 있다.
3. `SOURCES.md`로 핵심 주장과 근거를 추적할 수 있다.
4. 기존 사용자 작업은 그대로 남아 있다.
5. 발표자료 커밋이 현재 브랜치에 추가되고 GitHub `origin`에 푸시돼 있다.
