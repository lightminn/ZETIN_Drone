# AI 창업 캠프 모바일 드론 실습 설계

## 승인과 목표

이 설계는 2026-08-10 사용자 프롬프트에서 제품 방향, 디자인 방향, 구현 착수까지
승인된 요구사항을 구체화한다. 추가적인 일반 디자인 승인 단계 없이 이 문서를 기준으로
구현한다.

약 50명의 학생이 앱 설치, 로그인, 노트북, 순번 대기 없이 QR 코드로 동시에 접속해
다음 순서로 체험한다.

1. 스마트폰 또는 터치 입력이 Roll·Pitch와 가속도 표시에 어떻게 대응하는지 본다.
2. 같은 입력으로 외란이 있는 가상 드론을 수평에 가깝게 유지한다.
3. 로컬 결과를 즉시 확인하고 선택적으로 점수 서버에 제출한다.

이 앱은 교육용 시뮬레이션이다. 실제 기체, 펌웨어, 지상국과 통신하거나 실제 비행
성능을 주장하지 않는다.

## 검토한 접근

### 채택: 정적 학생 앱 + 선택적 같은 출처 점수 서버

- 학생 앱의 센서 변환, 입력 처리, 물리 시뮬레이션, 점수 계산을 브라우저에서 수행한다.
- 정적 파일만 배포해도 IMU 체험, 호버링, 결과, 재도전이 모두 동작한다.
- Python 표준 라이브러리 서버를 선택적으로 실행하면 정적 파일 제공과 점수 집계만
  추가된다.
- 50명의 계산 부하는 각 스마트폰에 분산되고 서버 장애가 학생 체험을 중단시키지 않는다.

### 기각: 모든 시뮬레이션을 서버에서 계산

동시 접속마다 상태를 관리해야 하고 네트워크 지연이 조작감과 공정성에 영향을 준다.
오프라인 복구도 어려워 이 행사의 핵심 조건과 맞지 않는다.

### 기각: 프레임워크 SPA와 관리형 실시간 데이터베이스

현재 범위에는 라우터, 계정, 빌드 파이프라인, 외부 서비스가 필요하지 않다. 정적
HTML/CSS/ES 모듈과 작은 HTTP API가 더 쉽게 감사·배포·복구된다.

## 정보 구조와 체험 흐름

학생용 `index.html`은 화면 단위 상태를 가진 단일 페이지다.

```text
시작
 ├─ 센서로 체험 → 권한 요청 → 첫 센서값 대기 → 중립 보정 ┐
 └─ 터치로 체험 ───────────────────────────────┤
                                                        ↓
                         IMU 관찰 → 가상 호버링 → 로컬 결과
                                                        ├─ 재도전
                                                        └─ 선택적 점수 제출
```

- 닉네임은 선택 입력이고 비워 두면 `익명`으로만 표시한다.
- 저장·제출하는 개인정보는 없으며 IP 주소를 애플리케이션 데이터로 보관하지 않는다.
- 센서 미지원, 비보안 컨텍스트, 권한 거부, 센서값 미수신은 모두 이유를 한 문장으로
  설명한 뒤 터치 체험 버튼을 같은 화면에 제공한다.
- 터치 모드의 IMU 화면은 조이스틱 입력으로 가상의 Roll·Pitch를 바꾼다. 따라서 센서가
  없어도 축 학습과 호버링을 모두 완료할 수 있다.
- 결과는 제출 전부터 DOM과 메모리에 유지한다. 제출 실패는 결과를 지우지 않는다.

발표자용 `presenter.html`은 별도 정적 페이지다.

- 학생 접속 URL을 표시하고 수정·복사할 수 있다.
- 저장소에 포함한 QR 생성기를 사용해 URL을 브라우저 안에서 QR SVG로 만든다.
- `/api/scores`를 주기적으로 조회해 제출 수와 상위 점수를 표시한다.
- API가 없으면 `점수판은 선택 기능입니다` 상태를 보여 주며 QR과 학생 앱은 계속 쓴다.

## 센서와 입력 경계

### 권한

W3C Device Orientation and Motion 규격과 MDN의 2026-02-09 문서를 기준으로 한다.
센서 인터페이스는 보안 컨텍스트에서 제공되며, `requestPermission()`이 있는
브라우저에서는 일시적 사용자 활성화가 필요하다.

- `DeviceOrientationEvent.requestPermission()`과 존재하는 경우
  `DeviceMotionEvent.requestPermission()`을 센서 시작 버튼의 `click` 처리 안에서
  직접 호출한다.
- 상대 자세만 사용하고 자력계 권한은 요청하지 않는다.
- `window.isSecureContext`가 거짓이면 HTTP 환경에서는 센서가 제한된다는 설명과
  터치 버튼을 제시한다.
- 권한 API가 없는 구현은 이벤트 리스너를 등록하고 실제 첫 이벤트를 기다린다.
- 유효한 자세 이벤트가 제한 시간 안에 오지 않으면 데스크톱 또는 센서 미제공 환경으로
  판단해 터치 모드로 전환할 수 있게 한다.

근거:

- W3C Device Orientation and Motion: https://www.w3.org/TR/orientation-event/
- MDN `DeviceOrientationEvent.requestPermission()`:
  https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static

### 변환과 보정

- 세로 화면을 기준으로 브라우저 `gamma`를 Roll, `beta`를 Pitch로 표시한다.
- 현재 유효 표본을 중립점으로 저장하고 이후 각도는 중립점과의 최단 각도 차로 계산한다.
- 표시 범위는 각 축 ±45°로 제한한다. 호버링 조작 입력은 ±20°에서 정규화해 ±1로
  제한한다.
- 표시에는 지수 평활화를 적용한다. 기본 계수는 새 표본 0.18, 이전 표시 0.82다.
- `devicemotion`의 `accelerationIncludingGravity`가 있으면 AX·AY·AZ를 m/s²로
  표시한다. 값이 없으면 `—`로 남기며 자세 체험을 중단하지 않는다.
- 이 값은 해당 브라우저가 제공한 스마트폰 센서 표시이며 드론 IMU 보정값이나 실제
  비행 검증값으로 설명하지 않는다.

### 터치 조이스틱

- Pointer Events 하나로 터치와 마우스를 처리한다.
- 원형 조작 영역의 중심에서 포인터까지의 벡터를 반지름으로 정규화하고 크기를 1로
  제한한다.
- `pointercancel`, `pointerup`, 포인터 캡처 해제 때 즉시 0으로 복귀한다.
- 왼쪽/오른쪽은 Roll, 위/아래는 Pitch이며 화면에 같은 축 이름과 화살표를 표시한다.

## 결정적 호버링 시뮬레이션과 점수

시뮬레이션은 60Hz 고정 시간 간격으로만 갱신한다. 렌더 프레임 간격은 누산기에 넣고
한 번에 처리할 최대 시간을 제한한다. 같은 초기 상태와 입력 표본 열은 같은 상태와
점수를 만든다.

- 상태: 경과 시간, Roll·Pitch 각도, 각속도, 누적 안정도, 현재 점수, 종료 여부.
- 입력: 각 축 -1부터 1까지의 보정 명령.
- 외란: 경과 시간만으로 정해지는 작은 사인파 두 개. 난수와 네트워크 시간을 쓰지 않는다.
- 물리: 입력 토크 + 결정적 외란 - 각도 복원항 - 각속도 감쇠항을 적분한다.
- 한 표본의 안정도는 각도 크기와 각속도 크기에 따라 0부터 100까지 감소한다.
- 화면 점수는 지금까지의 평균 안정도를 0부터 1000까지 반올림한 값이다.
- 도전 시간은 20초다. 종료 뒤 업데이트는 상태를 바꾸지 않는다.
- 재시작은 모든 물리·점수 상태와 입력을 초기화한다.

점수 수식은 `scoring.mjs`, 물리 갱신은 이를 소비하는 `challenge.mjs`에 두어 서로와
DOM에서 분리하고 Node 내장 테스트 러너로 직접 검증한다. 이 모델은 교육용 게임
모델이며 실제 펌웨어나 실제 기체 동역학과 동일하다고 표현하지 않는다.

## 선택적 점수 서버

`server.py`는 Python 표준 라이브러리의 `ThreadingHTTPServer`를 사용한다.

- 정적 파일: 학생·발표자 페이지와 로컬 자산을 제공한다.
- `POST /api/scores`: 점수 하나를 검증하고 메모리에 저장한다.
- `GET /api/scores`: 총 제출 수와 점수·안정도·모드·표시 이름만 포함한 상위 10개를
  반환한다.
- 저장소는 `threading.Lock`으로 보호한다. 50개 병렬 요청 중간에도 일관된 스냅샷을
  반환한다.
- `submission_id`는 한 결과의 재전송 키다. 같은 ID와 같은 내용은 기존 결과를
  반환하고 수를 늘리지 않는다. 같은 ID의 다른 내용은 409로 거부한다.
- 허용 필드와 범위를 명시하고 알 수 없는 필드, 잘못된 JSON·타입·범위, 큰 본문을
  4xx로 거부한다.
- 서버 재시작 시 순위는 초기화된다. 영속 저장은 이번 행사 시제품 범위가 아니다.
- API 실패·타임아웃은 클라이언트에서 `로컬 결과는 저장되어 있습니다`로 처리한다.

## 시각 설계

### 대상과 한 가지 화면 목적

대상은 드론 제어를 처음 접하는 캠프 학생이다. 각 화면의 한 가지 목적은 사용자가
자신의 기울임이 어느 축과 가상 기체 움직임으로 연결되는지 즉시 보는 것이다.

### 토큰

| 역할 | 값 |
|---|---|
| 비행 계기 배경 | `#071522` |
| 계기 표면 | `#0E2234` |
| UOS 파랑 | `#004094` |
| 실시간 하늘색 | `#48A9FF` |
| 안정 신호 | `#45E3C6` |
| 주의 신호 | `#FFBF5B` |
| 기본 글자 | `#F4F8FC` |
| 보조 글자·눈금 | `#91A4B7` |

장식용 그라데이션과 그림자는 사용하지 않는다. 오류에만 붉은색을 쓰고, 센서 미지원·
오프라인은 주의색 또는 중립색으로 표현한다.

### 글꼴과 형태

- 제목·본문: 기존 발표 번들의 Noto Sans CJK KR 400/500/700을 재사용한다.
- 수치·축·시간: `ui-monospace` 계열과 `font-variant-numeric: tabular-nums`를 쓴다.
- 모서리는 기존 발표와 같은 작은 4px 반경, 1px 계기 눈금, 각진 절단 모서리를 쓴다.
- 터치 대상 최소 높이는 48px이고 주요 CTA는 56px 이상이다.

### 레이아웃과 시그니처

카드 묶음 대신 화면을 세 영역의 연속 계기판으로 구성한다.

```text
┌ SIM / 실제 기체 미연결 ───────── 연결 상태 ┐
│                                             │
│        큰 인공수평선 + 기체 십자선          │
│        ROLL -02.4°   PITCH +01.8°           │
│                                             │
├ AX / AY / AZ ─────── 안정도 눈금 ──────────┤
│ 지금 할 행동 한 문장                        │
│ [넓은 주 동작 버튼]                         │
└─────────────────────────────────────────────┘
```

기억점은 화면 절반을 차지하는 인공수평선이다. 하늘과 지면을 평면색으로 나누고 센서
또는 시뮬레이션 Roll·Pitch에 따라 경계가 회전·이동한다. 이는 비행제어 맥락을 직접
표현하면서 기존 슬라이드의 파란 면과 각진 조형을 모바일 상호작용으로 번역한다.

자기 검토에서 처음 제안했던 여러 작은 텔레메트리 카드는 템플릿형 대시보드처럼 보여
제거했다. 하나의 큰 자세 계기, 얇은 데이터 레일, 한 개의 다음 행동만 남긴다.

## 접근성·반응형·복구

- 360×800과 390×844 세로 뷰포트에서 가로 스크롤이 없어야 한다.
- 작은 화면에서는 계기 높이를 `clamp()`로 줄이고 결과·설명은 세로 스크롤을 허용한다.
- 하단 CTA는 안전 영역 `env(safe-area-inset-bottom)`을 포함한다.
- 포커스 표시, `aria-live` 상태, 명시적 레이블, 충분한 대비를 제공한다.
- `prefers-reduced-motion`에서는 주변 애니메이션을 끄되 센서에 따른 필수 계기 이동은
  즉시 갱신한다.
- `visibilitychange`에서 도전 타이머가 백그라운드 시간을 한꺼번에 적분하지 않도록
  프레임 기준을 초기화한다.

## QR 자산

Kazuhiko Arase의 공식 `qrcode-generator` JavaScript 배포본을 저장소에 포함한다.
공식 저장소와 npm 패키지는 MIT 라이선스를 명시한다.

- 출처: https://github.com/kazuhikoarase/qrcode-generator
- 배포 버전: npm `qrcode-generator` 2.0.4
- 로컬 파일과 원문 MIT 라이선스를 `vendor/qrcode-generator/`에 함께 둔다.
- 런타임 CDN 또는 외부 QR API를 호출하지 않는다.

## 테스트 경계

### 자동 검증

- Node 단위 테스트: 권한 분기, 보정·변환·평활화, 조이스틱 벡터, 결정적 물리와 점수,
  종료·재시작, 제출 실패 결과 보존.
- Python 단위·통합 테스트: 유효/무효 요청, 중복 키, 50개 동시 제출, 정적 제공.
- 실제 Chrome CDP: 센서 API 미지원·허용·거부 합성 분기, 합성
  `DeviceOrientationEvent`, 터치 Pointer Event, 정적 서버에서 API 실패 뒤 결과 유지,
  발표자 API 미연결 상태, 두 모바일 뷰포트의 overflow·버튼 잘림, 스크린샷.
- 저장소 전체 테스트, `tools/check_repo_layout.py`, `git diff --check`, 금지 통신 API
  및 기존 발표/PPTX 변경 여부를 확인한다.

### 자동 검증이 증명하지 않는 것

- 실제 iOS Safari와 Android Chrome의 물리 센서 축·권한 프롬프트·샘플 주기.
- 현장 Wi-Fi에서 50대가 동시에 정적 자산을 받는 품질과 QR 인식 거리.
- 행사장 HTTPS 인증서 신뢰, 프로젝터 가독성, 실제 스마트폰 safe area.
- 실제 드론, 펌웨어, UDP, 시리얼, Bluetooth, USB 또는 비행 성능.

이 항목들은 행사 전 체크리스트에서 별도의 현장 확인으로 남긴다.
