# 드론 발표자료 시각 중심 개편 설계

## 목표

84장 HTML 기준본의 기술적 사실과 발표 순서는 유지하면서, 설명을 먼저 읽어야
이해되는 텍스트 카드형 슬라이드를 사진·영상·SVG 도판을 먼저 보고 설명을 따라갈
수 있는 슬라이드로 바꾼다. 교수 피드백이 집중된 4~11장은 자격·UAM·활용처·힘과
토크·군집의 핵심 관계가 화면에서 즉시 보이도록 우선 개편한다.

## 변경하지 않는 것

- 84장과 `의의 → 하드웨어 → 소프트웨어 → 시연·체험` 순서
- 현재 코드·로그·벤치·실비행의 증거 경계
- 슬라이드 9의 올바른 X형 쿼드콥터 배치와 슬라이드 10의 헬기–드론 토크 도판
- 기술 중심, 사업성 보조라는 발표 비중
- HTML/CSS/JS 기준본과 오프라인 자산 구조
- 사용자가 다시 요청하기 전 PPTX·PDF 산출물

## 시각 언어

- 배경은 흰색, 본문은 `#172334`, 핵심 벡터와 선택 상태는 UOS 파랑 `#004094`.
- 회색 `#516074`/`#718096`는 조건과 보조 설명, 금색 `#d49b00`은 경계·주의,
  청록 `#23836f`는 센서·관측, 적색 `#b04a55`는 외란·위험에만 쓴다.
- 새 SVG는 1180×450 또는 1180×474, Noto Sans CJK KR, 최소 24px이다.
- 숫자 카드, 장식용 그라디언트, 의미 없는 아이콘 묶음을 쓰지 않는다.
- 한 슬라이드는 한 관계, 한 SVG는 주요 라벨 4~6개만 사용한다. 문장형 설명을
  SVG 안에 넣지 않고, 실제 사진·영상·그래프가 있으면 SVG보다 먼저 사용한다.
- 제목은 비유·광고 문구 대신 `드론의 법적 분류`, `SIL 폐루프 구조`처럼 짧은
  명사형으로 쓴다.

## 슬라이드별 설계

### 의의 4~11장

- 4장: 법적 분류를 네 종류의 비행체 실루엣과 계층 화살표로 보여주고, X형
  쿼드콥터를 파란색으로 강조한다.
- 5장: 2~4종은 최대이륙중량 구간으로, 1종은 최대이륙중량 하한과 연료 제외
  자체중량 상한을 함께 보는 혼합 기준으로 표현한다. 우리 기체의 실제 무게 측정이
  선행된다는 경계를 유지한다.
- 6장: 고정익·헬리콥터·멀티콥터·eVTOL의 실제 형상과 장단점을 한 줄씩 배치하고,
  UAM은 기체가 아니라 기체·버티포트·운항·교통관리의 연결망으로 표현한다.
- 7장: 공연, 화물 운송, 시설·재난 감시, 국방 정찰 장면을 직접 그린 도판과
  임무별 핵심 사양을 연결한다. 국방은 작전 절차가 아닌 시스템 요구만 다룬다.
- 9장: 기존 네 힘 도판 아래에 `상승 / 호버링 / 하강 / 전후좌우`를 합추력과
  중력의 관계로 요약한다. Yaw는 10장의 토크 설명으로 연결한다.
- 10장: 현재 검증된 헬리콥터 꼬리로터와 쿼드콥터 CW·CCW 쌍 비교를 유지한다.
- 11장: 한 대에서 여러 대로 늘어날 때 공통 좌표·통신·상대 위치·대형 계획·충돌
  회피·집단 안전이 네트워크 위에 추가되는 모습을 보여준다. 후속 목표 표시는 유지한다.

### 하드웨어 21~31장

- 21~22장의 구성도와 표는 정확성을 위해 유지한다. 이미 사진과 CAD가 중심인
  23~31장도 구조를 바꾸지 않고, 장황한 제목과 중복 설명만 줄인다.

### 소프트웨어 33~73장

- 33장의 제어 흐름에는 기존 Python 영상 `cascade-loop-timing.mp4`를 사용한다.
  46장의 SIL, 63~64장의 Failsafe·착지 한계, 71장의 경쟁 상태는 라벨이 적은
  단일 목적 SVG로 바꾼다.
- 57장은 기존 벤치 그래프 `chart_mag.png`, 81장은 모터 위치와 출력 차이만 남긴
  단순 SVG를 사용한다.
- 기존 Python 영상 12개는 각 개념을 처음 설명하는 장의 주 시각자료로 유지한다.
- 수식·표가 필요한 장은 결과 곡선이나 상태 전이 도판을 먼저 두고 수식은 보조로 둔다.
- 코드 화면은 실제 코드 근거가 필요한 SIL 경계에서만 사용한다.

### 시연·체험 75~84장

- 실제 기체·모바일 화면·로그 그래프·테더 영상을 유지한다.
- 81장은 원시 필드 표를 줄이고 기체의 모터 위치와 출력 차이를 먼저 보여준다.
  정확한 검증 범위를 전달하는 82~83장의 표·단계 구조는 유지한다.

## 검증 계약

- Chrome에서 84장이 모두 렌더되고 텍스트 잘림과 단어 내부 줄바꿈이 없어야 한다.
- 새 SVG는 모두 로드되고 자연 크기가 1180×450 또는 1180×474여야 한다.
- 4~7장과 11장은 각각 하나 이상의 외부 SVG를 주 시각자료로 사용해야 한다.
- 9장은 상승·호버링·하강·전후좌우를, 10장은 헬기·쿼드콥터의 토크 차이를 표시해야 한다.
- 14개 MP4의 자동재생·반복·리셋 계약은 바뀌지 않아야 한다.
- 교수 피드백에 관한 모든 수치·분류·개념은 `SOURCES.md`의 공식·1차 근거와 연결한다.
