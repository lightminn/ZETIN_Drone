# BMM350 Yaw 융합 — HW 벤치 테스트 절차

`dual_imu_cascade_pwm` + BMM350 yaw 융합(branch `feat/bmm350-yaw-fusion`) 대상.
SIL은 융합 수학만 검증한다. 이 절차가 실센서·실간섭을 검증한다.

명령/텔레메트리 (빌드 확정): **`magcal 1`**=캘리브 시작(disarmed에서만), **`magcal 0`**
=중지+샘플 수·축별 span 출력, **`mag 1`/`mag 0`**=융합 ON/OFF(기본 OFF), **`magc x y z`**
=모터 전류 간섭 보정 계수(µT/µs) 3축 런타임 설정. 텔레메트리 **`MagHeading`**(31번,
틸트+간섭보정 heading) + **`Yaw`**(=angleZ, 융합 heading) + **`Mag_X/Y/Z`**(32~34번,
평상시 보정 후 자기장, `Mag_Cal_Active=1` 동안 보정 전 raw µT) +
**`Mag_Cal_Active`**(65번, 캡처 구간 식별).

> **결과 요약 (2026-07-27 완료):** 1~3 통과, 4에서 모터 전류 간섭 발견(호버 +13°,
> corr 0.80) → **raw XYZ 도메인 보정으로 제거**(heading slope +3.64→+0.02°/100µs).
> 계수 `mag_comp_x/y/z` 펌웨어 baking + 커밋(1497d74). 상세는 아래 4단계.

> **정정 (2026-08-04):** 아래 2026-07-27 결과는 당시 min/max hard-iron
> 절차로 얻은 날짜 기록이므로 수정하지 않는다. 현재 절차는 min/max 상수를
> 출력하지 않고, raw CSV를 Li & Griffiths 제약 타원체 + MAD 클리핑으로 피팅해
> hard/soft-iron을 함께 갱신한다.

## 0. 안전 / 준비
- **프롭 OFF** 로 시작(1~3단계는 무추력). 4단계만 프롭 ON.
- BMM350는 PCB 상 고정(움직이면 캘리브 무의미).
- 주변 **강자성체(공구·스피커·철제 책상다리) 치우기** — hard-iron 오염.
- 텔레메트리 모니터: `Yaw`(융합 heading) + `MagHeading`(틸트·간섭보정 heading) 관찰.
- ⚠️ BMM350 축 부호 기본 `+X/+Y/+Z` (미확인) — 2단계에서 회전과 heading이 **반대**로 가면 부호 반전 필요(아래 참조).

## 1. hard/soft-iron 캘리브레이션 (프롭 OFF, **disarmed**)
1. 지상국 CSV 로그가 기록 중인지 확인하고 `magcal 1`을 보낸다(armed면 거부).
   텔레메트리 `Mag_Cal_Active=1`과 변하는 raw `Mag_X/Y/Z`를 확인한다.
2. 드론을 **모든 방향으로 천천히 회전**한다. yaw 2~3바퀴뿐 아니라
   roll/pitch도 각각 충분히 기울여 구면 방향 커버리지를 만든다.
3. `magcal 0`을 보낸다. 시리얼의 샘플 수와 X/Y/Z span을 캡처 기록과
   대조한다. 펌웨어는 여기서 offset을 계산하거나 출력하지 않는다.
4. 저장소 루트에서 다음을 실행한다. 기본 동작은 CSV의
   `Mag_Cal_Active == 1` 행만 자동 선택한다.

   ```bash
   /home/light/anaconda3/bin/python scripts/magcal_fit.py logs/flight_log_YYYY-MM-DD_HHMMSS.csv
   ```

5. 커버리지 경고/거부, 피팅 반경·축비, 보정 전후 `|B|` 산포와 추정 heading
   오차를 확인한다. 통과한 출력의 `MAG_HARD_IRON`과 `MAG_SOFT_IRON` 블록을
   펌웨어에 붙여 넣고, 함께 출력된 `W @ 기존계수` 값으로 `mag_comp_x/y/z`를
   갱신한다.
6. 재빌드·재플래시한 뒤 새 로그로 `|B|` 산포와 heading 안정성을 다시
   확인한다. 소프트아이언을 바꾸면 `mag_comp` 의미도 바뀌므로 4단계 모터
   간섭 검증도 반드시 다시 수행한다.

## 2. Heading 추종 (프롭 OFF)
- `mag 1` 로 융합 ON. 드론을 **천천히 회전**(폰 나침반으로 실제 방위 참고 가능).
- **불변식**: 기체를 한쪽으로 돌리면 `Yaw`(heading)도 그 방향으로 변하고, 멈추면 그 값에 **머문다**. 회전과 heading이 **반대로 가면 부호 반전** → 정지 후 firmware의 mag 축 부호/틸트보정 부호를 뒤집어 재검증(SIL "tilt compensation inverted"가 이걸 잡는 케이스).
- 틸트 섞어 회전해도(기울인 채 yaw) `MagHeading`이 흔들리지 않는지(틸트보정 확인).

## 3. 무드리프트 확인 (프롭 OFF) — 핵심
- 드론을 **한 방위로 고정하고 수 분 정지**. `Yaw` 로그를 받는다.
- **비교**: `mag 0`(자이로만)일 때는 수 분에 걸쳐 heading이 서서히 드리프트(°/분)하고, `mag 1`일 때는 **한 값에 고정**돼야 한다. 이 차이가 이 기능의 존재 이유.
- 통과 기준: `mag 1` 5분 드리프트 < 자이로온리 대비 현저히 작음(사실상 0 근처).

## 4. 모터 간섭 (프롭 ON, 고정·저속) — 최대 리스크
- **기체 단단히 고정, 프롭 ON, PSU 전류제한.** `mag 1`.
- 스로틀을 **호버 근처(~1360)** 까지 단계적으로 올리며 각 레벨에서 `Yaw`(heading)를 관찰.
- **판정**: 모터 전류가 지자기를 오염시키면 스로틀 올릴 때 heading이 **튀거나 스로틀에 비례해 이동**한다.
  - heading이 스로틀과 무관하게 안정 → **간섭 허용** ✅ → 비행에 mag-yaw 사용 가능.
  - heading이 스로틀 따라 크게 이동 → **간섭 심함** → 완화 필요.
- 간섭량(°/스로틀레벨)을 기록.

### 실측 결과 + 완화 (2026-07-27)
간섭이 실재했다: 호버에서 **+13°**, `corr(throttle, MagHeading)=0.80`, 올림/내림 가역 →
시간 드리프트가 아닌 전류 간섭. **heading(°) 도메인 slope는 방위마다 달라 재현 안 됨**
(런별 +1.95 / +4.6 / +3.64°/100µs). 원인: 간섭은 body-frame ΔB(µT) 벡터인데 heading
투영이 방위 의존.
- **해법 = raw XYZ(µT) 도메인 보정**(방위 무관). `Mag_X/Y/Z`를 throttle에 회귀 →
  ΔB per µs 피팅(주로 X축: +0.0075µT/µs). 펌웨어가 `mag.{x,y,z} -= mag_comp_{x,y,z}·
  (base_throttle−1000)`을 틸트보정 전에 적용. 런타임 `magc x y z`, 기본값 baking.
- **검증(log 024330, comp ON):** MagHeading throttle slope **+3.64 → +0.02°/100µs**
  (corr 0.008), `Mag_X` slope ≈ 0. 잔차 ~2.8°는 throttle-무관 노이즈(융합 τ≈4s가 흡수).
- **확정 계수:** `mag_comp_x=+0.007497 mag_comp_y=−0.001218 mag_comp_z=−0.000640`
  (log 023805 특성화). **CAVEAT:** 계수 크기는 배터리 상태로 ~2× 변동 → 대부분 제거하나
  방전 시 잔차 증가. 90° 방위 무관 확인은 생략(구조상 방위 무관).
